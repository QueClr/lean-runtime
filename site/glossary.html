Glossary

Each term has one meaning on every page of this site.

A821
The id of the finding about the descriptors that native Lean opens before main. Option C was the first design: the same descriptors through rustix, with epoll descriptors in place of the io_uring rings. Since quirks-2 the rings are real, made with the io-uring crate. See io.
Batch
One unit of work on lean-runtime, on its own branch, that merges as a whole. Examples: semantics-1, io-2, sched-1.
BigNat, BigInt
The big-number traits of semantics. Each translator implements them with its own library: lean2rr with GMP, leanrs with malachite. The Nat and Int rules are generic over them.
ByteSink
A trait that a translator implements on its own object. lean-runtime appends a result of unbounded size (a line, a path, an environment value) to it. So the glue copies nothing.
CAF (constant applicative form)
A top-level constant with no parameters. Native Lean computes it once, at start or at first use. A translator can compute such a closed term when it translates. So a test whose values are all CAFs or literals never reaches the runtime; tests read their inputs from argv or stdin.
Case (program case)
A whole Lean program in tests/cases/, with its stdout, stderr and exit code from a native build. See Testing.
Context
A stack on which code runs, in sched. main's context is the thread's own stack. Every other context is a corosensei coroutine with a stack of its own.
corosensei
The vetted Rust crate that switches stacks for sched (version 0.3.4).
Coroutine
A function with a stack of its own that can stop in the middle (suspend) and go on later (resume). sched runs every task context except main's as a corosensei coroutine.
Coverage
The count of the extern symbols of Lean 4.34.0's Init and Std that lean-runtime implements. See Status.
Decision (O1 to O12, Q1 to Q10)
A decided design point, recorded with its date in the projects' coordination notes. O-numbers are the owner's decisions. Q-numbers are the agreed answers to the open questions of the shared-runtime proposal.
Delayed error
An error that libuv keeps on a socket and reports at the next call, not at the call that caused it. Example: bind to an address in use succeeds, and the next listen reports EADDRINUSE (net).
Deferred task
A task that does not run when it is made. It runs later, at the first of a few fixed points, for example when its value is needed. See sched.
Deviation
A documented, intended difference from native Lean. A case lists it in its deviations field. For a translator's own deviation, the expected output stays native's, and the deviation's outcome is also allowed. When native's outcome is a Lean bug, the case expects the correct outcome and keeps native's beside it, in its native field. A row for a lifted limit does the same with the definition's result. leanrs names its deviations DVn; lean2rr lists them in section 10 of its translation plan.
Drain (free)
A translator's release of a value and of everything it holds, one object after the other. No context may suspend during a drain. A promise dropped there is resolved after the drain. See the wait cores.
DNS helper threads
The two threads that net starts at the first name lookup. They only call glibc's lookup functions and pass plain data back to the event loop (net).
DVn
leanrs's id for a deviation. Some ids also name the decision on that deviation, for example DV5 (debug primitives) and DV10 (the clock's origin).
Effect point
A yield point before an output, a flush, a process spawn or an exit. There, a task that was queued 5 ms ago or more runs first.
ELF constructor
A function that the program loader runs before main and before Rust's runtime starts. One opens the startup descriptors early enough: the crate's (feature startup-fds), or one in the glue. glibc calls it with main's arguments, so lean-runtime has one of its own for the process title (feature proc-title). The crate's constructors use no global allocator (AR-36).
errno model
lean-runtime's own copy of C's errno, one per thread. rustix does not set libc's errno, so the crate sets its copy as the C call would.
Extern
A Lean declaration marked @[extern]. Native Lean implements it with a C function.
FILE
glibc's buffered stream. Native Lean uses it for every handle. io::cfile is a model of it in safe Rust.
Get area, put area, read-ahead
Parts of a FILE buffer. The get area holds bytes read from the descriptor; the bytes that Lean has not read yet are the read-ahead. The put area holds pending output that has not reached the descriptor yet.
Gate
A 4-byte record in a translator's cell: the context that computes the cell's value, if any. Other contexts wait for that computation. See the wait cores.
glibc
The GNU C library. The reference host has glibc 2.39.
Glue
The thin code in each translator between its own values and lean-runtime. It converts its objects to views, calls the crate, and turns plain data back into its objects. It also does the few steps that the crate's safe code cannot do. See Architecture.
GMP, malachite
Big-number libraries. Native Lean and lean2rr use GMP (C); leanrs uses malachite (Rust).
Hub
The scheduler's loop on main's stack. It resumes the contexts one at a time. Every switch between contexts goes through it.
INTERNAL PANIC
Lean's message for a failure of the runtime itself, for example INTERNAL PANIC: out of memory. The process then ends, with status 1 (or an abort under LEAN_ABORT_ON_PANIC). A Lean panic! is different: it prints a message and the program goes on.
io feed
libuv's way to run a socket's callback at the loop's next turn, for example after a write that finished at once. Here it is a timer of the event loop that is due at once (net).
IO need
The mark of a pure task that an IO task waits for, directly or through other pure tasks. A pure task with IO need starts as an IO task does.
IO task, pure task
An IO task comes from IO.asTask, IO.mapTask or IO.bindTask, and always runs. A pure task comes from Task.spawn, Task.map or Task.bind. If the program drops a pure task before it starts, Lean deletes it.
Judge
A reviewer who decides whether a suspected Lean bug is real, by the rule.
LB-nn
The id of an entry in docs/lean-bugs.md: a confirmed Lean bug, a lifted limit, or a "not a bug". See Lean bugs.
lean2rr, leanrs
The two translators for which lean-runtime is built. lean2rr translates compiled Lean code to Reussir; leanrs translates it to Rust.
libm
The C math library (sin, pow, cbrtf and the others). Native Lean calls glibc's libm for the Float and Float32 functions.
libuv
The event-loop library that Lean 4.34.0's runtime links (version 1.48.0).
Line-buffered
A stream that writes its buffer out at each newline. glibc makes a stream line-buffered when its descriptor is a terminal.
MAX_BITS
BigNat::MAX_BITS: the size, in bits, of the largest result a big-number backend accepts. A rule tests the result size against it before it calls the backend. leanrs's value is 239.
Miri
Rust's interpreter that finds undefined behaviour. scripts/check.sh runs it on the unsafe-fast configurations when LEAN_RUNTIME_MIRI=1 is set. One of them has proc-title, with the unit tests of the native quirk.
Native Lean
Lean's own build: the Lean compiler emits C, which links with Lean's C runtime. A native build with Lean 4.34.0 gives every expected value.
Native quirk
A behaviour of native Lean that no safe API can reproduce. lean-runtime writes such an item with unsafe code, in a small file of its own (decision of 2026-10-04). Each has an entry in UNSAFE.md and a written proof. The three so far: setProcessTitle writes the title into the arguments' memory (io). An ELF constructor opens the startup descriptors (io). Lean's stack-overflow report knows the guard pages of the contexts (sched). Each is built only with a feature of its own: proc-title, startup-fds and stack-overflow.
O12 (speed floor)
The decision of 2026-10-03: the default, safe build of every shared function must be at least as fast as Lean 4.34.0's native runtime. unsafe-fast is for going further, not for reaching the floor.
Oracle
The source of expected values. For rows it is scripts/oracle, a Lean program built natively; for program cases, the native build of the case. In the glibc differential test, glibc itself is the oracle.
Pin
The lean-runtime commit that a translator uses. A translator moves its pin only after its own test suite passes.
Polling point
A yield point at a clock read, a task-state query, IO.checkCanceled, or (in a program with tasks) every 1000th ST.Ref read.
Priority
The order in which queued tasks start: Lean's priorities 0 to 8, and dedicated tasks, which natively get a thread of their own.
proc-title
The Cargo feature of the process title's native quirk: setProcessTitle writes the title into the arguments' memory. It turns on io, and lean2rr turns it on. Without it, the crate has no unsafe code, and setProcessTitle fails with ENOBUFS.
Promise
A task without a computation: IO.Promise. Its first resolution stores the value.
Reussir
The language that lean2rr translates to.
Row
One function call with its expected result, recorded from native Lean 4.34.0. Rows are in tests/cases/<area>/<area>.rows.toml. See Testing.
rustix, nix, io-uring
Vetted Rust crates for system calls. They hold the unsafe code, so io stays free of it. The native quirks are behind proc-title, startup-fds and stack-overflow. io-uring makes the io_uring rings that libuv opens at startup.
sched-io
The batch of cooperative blocking IO and the event loop. When tasks exist, reads, writes and waits on pipes and child processes let the other contexts run instead of blocking the one thread. See sched.
Schedule-dependent
A case whose native outcome depends on thread timing. The case records every outcome seen; each one is allowed.
stack-overflow
The Cargo feature of Lean's stack-overflow report, a native quirk: a SIGSEGV handler that knows the guard pages of the contexts. It turns on sched, and lean2rr turns it on. Without it, a task that overflows its stack ends with a plain SIGSEGV (status 139).
Started (pure task)
A pure task that a worker would have started, but that has not run yet. It cannot be deleted any more. See the pure-task rule.
Startup descriptors
The descriptors that libuv opens before main in native Lean: epoll, two io_uring rings (when libuv uses io_uring), two pipes and an eventfd.
startup-fds
The Cargo feature of the startup constructor, a native quirk: an ELF constructor of the crate opens the startup descriptors before Rust's runtime starts. It turns on io, and lean2rr turns it on. Without it, a translator's glue writes that constructor itself.
Std.Sync
Lean's synchronization library: mutexes, condition variables, channels, barriers, semaphores. sched implements its four base primitives; the rest is Lean code.
Sticky indicators
The end-of-file and error flags of a FILE. Lean's read and getLine clear both flags when they reach the end of the file. An error flag otherwise stays set, so a later call still reports its errno.
Sync dependent
A dependent task (from map or bind) made with sync := true, or at priority LEAN_SYNC_PRIO. It runs at once on the context that finishes its source, without the queue.
Threads mode
lean-runtime's second scheduler, sched::mt, behind the feature threads: Lean's task manager on real OS threads. A build has either threads mode or the single-thread sched. See Threads mode.
Translator
A compiler that takes compiled Lean code and emits code in another language. lean2rr and leanrs are translators.
Twin
Two programs that do the same work. A Rust twin of a case makes the same calls through lean-runtime as the case's Lean program. In a benchmark pair, each side is the other's twin.
unsafe-fast
An opt-in Cargo feature for faster unsafe versions of functions. Each needs the same behaviour as its safe twin, a proof in UNSAFE.md, and Miri checks. There are none yet.
View
A borrowed look at data that the caller owns: &[u8] or &str. Small plain values (u64, f64) pass by value.
Word, word helper
A word is a number that fits a machine word (Small). A word helper (*_small) is a rule on words only, for a translator's own fast path.
Worker, pool task
Native Lean runs tasks on a pool of worker threads. A pool task runs on one of them, not on a dedicated thread. sched keeps the number of workers (LEAN_NUM_THREADS, or the number of processors) as a limit on running contexts. Threads mode has real worker threads, as natively.
Yield point
A call where the running context lets other contexts go first. The kinds: effect points (before an output, a flush, a process spawn, an exit), polling points, and sleeps.
Yielder
corosensei's handle through which a coroutine suspends itself. The glue's Glue::suspend reaches it through a raw pointer, the one dereference in the glue.
