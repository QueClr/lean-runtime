# site/: the readable overview of lean-runtime

This folder is a small static website that explains lean-runtime's architecture to people: what the crate is, its three modules, what stays in each translator's glue, how it is tested, the Lean bugs it does not copy, and its status, with hand-drawn diagrams and a glossary. To read it, open `site/index.html` in a browser; it needs no network and no JavaScript. The text follows about 80% of ASD-STE100 (Simplified Technical English): short sentences (about 20 words, at most 25), active voice, one idea per sentence, the same word for the same thing, lists for steps and sets, and every term defined once on the glossary page. The diagrams are inline SVG, drawn by hand, with the colours of `style.css` (the overview's first figure has the key). The markdown docs (`README.md`, `UNSAFE.md`, `docs/` with `docs/development.md`, the module docs in `src/`) stay the detailed reference: the site summarizes them and links to them. Update the site when the architecture changes (a new module, batch, decision or Lean bug), not for every detail.

## Editing

| File | What it is |
|---|---|
| `src/pages/NAME.html` | The body of page `NAME.html`. Edit these for the text. |
| `src/diagrams/NAME.svg` | A diagram, included in a page body with `{{svg:NAME}}`. |
| `build.py` | Builds every page: the shared header, navigation and footer, the diagrams, and `{{v:NAME}}` values counted from the repository (rows, cases, benchmark pairs, the Lean version). |
| `style.css` | The style (light mode). |
| `*.html` | Generated by `build.py` and committed, so that a clone can open them. Do not edit them by hand. |

```
python3 site/build.py           # write the pages
python3 site/build.py --check   # write nothing; fail if a page is out of date or a check fails
```

`build.py` needs Python 3's standard library only, and its output depends only on the repository's files. It writes nothing when a source or a page holds a forbidden string (local paths, private notes: the repository is public), when a diagram is not well-formed, or when a link, a fragment or a page's tags are broken. `scripts/check.sh` runs `--check` first. It warns, and `--check` fails, on a sentence over 25 words and when the sources have moved on from the pages: a Lean-bug entry, a module or a feature that its page does not name, or a branch that the status page lists as in progress but whose files are now in the checkout. Hand-written facts that can go stale (the status page, the coverage figure, the decisions) carry their date in the text: update them when they change. After a change to a diagram, look at it in a browser; text in SVG does not wrap, so keep labels short.
