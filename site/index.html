lean-runtime

lean-runtime is one Rust crate. It holds the behaviour of Lean 4.34.0's runtime. Its repository is named lean-runtime-rs to mark it as a Rust reimplementation, not Lean's own runtime. It is built to be shared by two Lean translators: lean2rr and leanrs.

What it is

  • A Lean program uses runtime functions: numbers, strings, files, tasks and more.
  • Native Lean gets these functions from its C runtime (lean.h and src/runtime/*.cpp).
  • lean2rr translates compiled Lean code to Reussir. leanrs translates compiled Lean code to Rust. Neither uses Lean's C runtime.
  • lean-runtime gives both translators these functions in Rust. It holds the part that does not depend on how a translator stores Lean values.

Why one shared crate

Decision (2026-10-03): one runtime for both translators.

  • Every runtime function is in lean-runtime, written once, in safe Rust.
  • Each translator keeps only thin glue for its own value layout.
  • No translator keeps its own copy of a function. There is no fallback per function.
  • A fix in lean-runtime fixes both translators. A test in lean-runtime checks both.
  • The code comes from both projects. Each module, and in semantics each function, names the code it came from: lean2rr's runtime, leanrs's runtime, or new code.

Goals

Same results

A translated program gives the same stdout, stderr and exit code as the native build with Lean 4.34.0.

Safe Rust

The default build has no unsafe code: #![forbid(unsafe_code)]. System calls go through vetted crates.

Speed floor (O12)

The default build of each function must be at least as fast as Lean's native runtime.

No copied Lean bugs

Where Lean's runtime is wrong, lean-runtime does the right thing. A judge confirms each bug first.

  • Same results. The expected values of every test come from native Lean 4.34.0 on aarch64 Linux with glibc 2.39. Both translators run on that host.
  • Safe Rust. The opt-in feature unsafe-fast can add faster unsafe code later. Each such part needs a written proof in UNSAFE.md. There are no entries yet.
  • Speed floor. A safe function that is slower than native is not merged as the default. The benchmark pairs exist, but nothing is timed yet. Timing runs only in sessions that the owner approves.
  • No copied Lean bugs. See Lean bugs.
