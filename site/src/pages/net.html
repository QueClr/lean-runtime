The net module

net (feature net) is Lean 4.34.0's network externs: TCP and UDP sockets, name lookups and interface addresses. It runs on the scheduler's event loop. In threads mode, it runs on the loop thread, as natively.

The module came with batch net-1. The feature net also turns on io. It needs a scheduler: sched or threads (batch net-threads). A translator admits the module for each program that uses the network.

The model

Natively, one thread runs libuv's loop for the whole program. An extern starts an operation and returns a promise. Later, the loop thread finishes the operation and resolves the promise.

Here, each socket copies the state of one libuv handle:

  • libuv's flags: readable, writable, bound, shut down, end of file;
  • its queues of writes, and its connect and shutdown requests;
  • the promises that Lean's object keeps.

The system calls are libuv's, in libuv's order. When libuv makes a call in the calling thread, the extern makes it. Examples: bind, listen, and the first write of a send. When libuv's loop thread makes a call, a callback on the scheduler's loop context makes it. Examples: reads, the rest of a write, accept4.

The callbacks resolve the promises on the loop context. So the waiting tasks wake there, as natively on the loop thread. In threads mode, the same code runs on the loop thread, and each extern holds the loop lock (threads mode).

Example: a client sends 16 MiB to a server that waits before it reads.

  1. The send writes the part that the socket accepts, and queues the rest.
  2. A shutdown stops new sends at once, and waits for the queue.
  3. The server reads. The loop sees that the socket is writable and writes the next part.
  4. When the queue is empty, the loop shuts down the write side and resolves both promises.

What the glue does

  • Promises. An operation takes a closure that holds the translator's promise. The crate calls the closure with the result, or drops it when Lean cancels the operation.
  • Data. A send keeps a view of the translator's buffers until the write is done. Nothing is copied.
  • Buffers. A receive calls back to the translator to allocate its ByteArray, where native allocates it. The bytes go straight into it.
  • Lifetime. A socket closes when the translator drops its last handle. A pending operation keeps the socket open until it ends, as natively. The loop's callbacks hold only the socket's number, so the loop never keeps a socket open (net-2).

Name lookups

libuv runs name lookups on its thread pool. Here, two helper threads call glibc's getaddrinfo and getnameinfo through the dns-lookup crate. The first lookup starts them.

  • The threads get plain data and send back plain data. No Lean value goes to another thread.
  • They wake the loop through the loop's eventfd. The loop context then resolves the promise.
  • They are not Lean-visible parallelism: they only wait in the C library.
  • At exit, the program waits for the lookups that run, as natively. It drops their results.

The hints are libuv's: socket type 0 and protocol 0. So glibc gives one entry for each socket type. For example, localhost with an empty service gives 127.0.0.1 three times.

What a program sees

  • A new socket has no descriptor until bind, connect or listen. Before that, the name queries and send fail with EBADF.
  • bind sets SO_REUSEADDR. An address in use is reported by the next listen or connect, not by bind.
  • One receive at a time on a socket. A second one fails with EALREADY.
  • A UDP datagram larger than the buffer is cut to the buffer's size.
  • The errors have native's texts, for example connection refused with code 111.

Native bugs it does not copy

Ten native bugs are recorded as Lean bugs: LB-21 to LB-28, LB-50 and LB-51. Each has a case that expects the correct result.

  • A second accept keeps the native event loop locked (LB-21).
  • A long IPv6 multicast address aborts the native process (LB-22).
  • keepAlive with a delay of 0 gives the wrong error (LB-23).
  • Two failures leak a socket (LB-24, LB-25).
  • recv? 0 at the end of the stream gives an error, not none (LB-26).
  • A name lookup that ends during the exit can crash native (LB-27).
  • A shutdown during a connect never happens natively (LB-28).
  • A shutdown during a slow connect makes the connect succeed before the connection exists (LB-50).
  • waitReadable at the end of the stream gives true, not false (LB-51).

Limits

  • Native's loop thread runs as soon as a socket is ready. With the single-thread scheduler, the loop runs when the program waits, sleeps or reaches a polling point. A program that only computes delays the callbacks. In threads mode, the loop thread runs as natively.
  • Two lookup threads, where libuv's pool runs at most two slow jobs at a time.
  • The tests use the loopback interface only. The DNS case uses localhost and numeric hosts, so it depends on the host's /etc/hosts.
