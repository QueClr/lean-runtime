Lean bugs we do not copy

lean-runtime copies Lean 4.34.0's C runtime, with one exception. Where Lean's runtime is wrong, lean-runtime and both translators do the right thing.

The rule

A behaviour is a bug only after a judge gives a verdict. The verdict needs three things:

  1. the C source lines that cause it;
  2. why it is wrong: the C standard, POSIX, Lean's own documentation or evident intent, or lost data or a crash;
  3. a minimal native repro that shows a wrong value, not only an odd symptom.

Anything that is not confirmed is followed exactly as native does it.

Decision (2026-10-03): these bugs are not reported upstream. They are recorded in docs/lean-bugs.md only. Each translator also lists them among its intended differences. The cases of LB-01, LB-02 and LB-03 are on branch cases-xt, not on main yet.

Confirmed bugs

IdWhat native Lean doesWhat lean-runtime and the translators do
LB-01A multi-threaded IO.Ref.get can undo a concurrent set, so the ref goes back to its old value.Both translators' ref cells (glue) make every operation atomic: a completed set is seen by every later get. (Upstream fixed it in Lean 4.35.0-rc1.)
LB-02After output on a handle, a read of a whole buffer or more makes glibc drop the pending output.It writes the pending bytes first, then reads.
LB-03An error without a file name (getCurrentDir after its directory was removed) crashes with SIGSEGV instead of raising an IO.Error.It raises the IO.Error, with the file name "".
LB-13After main returns, a pool task enqueued when no pool worker is left never runs. Its effects are lost, and a wait on it hangs.The task runs, and a wait on it returns (sched, branch sched-1). Both judges confirmed it on 2026-10-03; its entry and its case are not in the repository yet.

Lifted limits

A limit is a place where Lean's definition has a value but the native runtime stops. A limit is not a bug. Decision (2026-10-03): "if we can lift the restrictions, then we can lift them". So the shared rules impose no cap: they compute the definition's result as far as the backend can (MAX_BITS).

IdWhere native Lean stopsWhat lean-runtime does
LB-04Nat.shiftRight by 232 or more, of an operand with that many bits: INTERNAL PANIC.Computes the result.
LB-05A Nat beyond GMP's limb count: GMP raises SIGFPE (status 136), with no message.Above the backend's MAX_BITS, both translators end with INTERNAL PANIC: out of memory, exit 1.
LB-06ByteArray.copySlice with an offset or length of 264 or more: INTERNAL PANIC: out of memory.Returns the definition's clamped copy.
LB-11Nat.pow with an exponent of 232 or more: INTERNAL PANIC, also for the bases 0 and 1.Computes the result for the bases 0 and 1, and for other bases while it fits MAX_BITS.
LB-12Nat.shiftLeft of a nonzero value by 232 or more: INTERNAL PANIC.Computes the result while it fits MAX_BITS.

Above MAX_BITS, these rules print native's own message for an exponent or shift of 232 or more.
