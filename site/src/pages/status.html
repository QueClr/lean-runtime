sched-ioCooperative blocking IO: reads, writes, flock and waitpid let the other tasks run (details). The scheduler's event loop, and Std.Internal.UV's loop, timers and signals on it; the taskio/ and uvloop/ cases.
cases-xtProgram cases from lean2rr's cross-test of leanrs's fixtures, cases for LB-01, LB-02 and LB-03, and cases for two decisions (DV5, DV10).
quirks-1IO.initializing, allocprof, and the write of setProcessTitle into the arguments' memory. That write is the crate's first unsafe item, a native quirk with its proof in docs/native-quirks.md. Since proc-title (2026-10-04) it is built only with that feature.
quirks-2Real io_uring rings among the startup descriptors, made and mapped as libuv makes them, through the io-uring crate, in place of option C's epoll stand-ins. A case checks the rings' /proc/self/fdinfo lines and mappings, and the polling ring's kernel thread.
cases-tasks-1Program cases for tasks and for two io findings, recorded natively; scripts/cases.py runs every case under a memory cap.
net-1The net module, behind the feature net: Std.Internal.UV's TCP, UDP, name lookups and interface addresses, on sched-io's event loop. It covers all 34 network symbols. LB-21 to LB-28, each with a case that expects the correct outcome; the cases use the loopback interface only.
sched-2The last three Task/Promise symbols. The private getOrBlock! is a crate item; Task.pure and Promise.result? are glue (docs/sched.md, "The glue"). A task finishes in native's order: it stores its value, runs its dependents, then wakes its waiters. LB-32 and its cases.
fixes-1Fixes and API requests from the translators (AR-1 to AR-3, AR-5 to AR-8). IO.Process.output stops reading when its output is out of memory, and the exit waits for the background output drains. A dropped stream whose flush would block gives its bytes to a writer thread. An exit does not wait for a reader that holds a stream (LB-29). A failure to open the startup descriptors ends with an internal panic (LB-30, LB-31).
Case marksDeviation marks on the program cases, from two of leanrs's adoption runs (the second for AR-13). DV2 marks the cases that leanrs refuses or runs eagerly until it adopts sched, net and the quirks. On 2026-10-06, other cases have DV5, DV6, DV11, DV15, DV18, DV19, DV20 or DV26. So scripts/cases.py check --translator leanrs reports them as deviations, not failures.
proc-titleThe feature proc-title (AR-14). The write of the process title (quirks-1) is built only with it, and lean2rr turns it on. Without it, io has no unsafe code: setProcessTitle fails with ENOBUFS, and getProcessTitle gives argv[0].
sched-3A wait runs the awaited task on the waiter's stack only when a free worker would take that task next (AR-10). Otherwise it blocks, and the scheduler starts the queue head on its own context. At the polling threshold, a task-state query starts the queue head on its own context and yields (AR-9). So tasks start in native's order. A task that waits for main no longer hangs the program when main polls it. Lean's stack-overflow report for tasks, behind the feature stack-overflow (AR-11): the second native quirk. lean2rr turns it on.
net-2The net module without Weak references (AR-12). The event loop's callbacks keep only a socket's number. They find the socket in a registry of open sockets. A dropped socket still closes at once.
sched-4A pool task that waits forever on itself frees its worker (AR-15). A pool task's worker stays busy while its sync dependents run (AR-16). The first known difference of the deferred model, LSCHED-01.
io-smallSmall io fixes for the translators (AR-17 to AR-20), such as the startup signal pipe without sched.
threads-1Threads mode (T1): sched::mt, Lean's task manager on real threads, behind the feature threads.
fixes-2The stop of a timer or a signal watcher as Lean's master branch does it (LB-33, LB-34), and API requests AR-22 and AR-23.
threads-2io and Std.Internal.UV in threads mode (T2). In both modes, a pool worker keeps its streams and errno from one task to the next (AR-24).
fixes-3A started pure task keeps its worker until it runs (AR-25), with the known differences LSCHED-02 and LSCHED-03. API requests AR-27 to AR-33.
threads-3The second test driver (T3) runs every tasks/, sync/, refs/ and taskio/ case in threads mode, 5 times. It shares its Rust ports with the single-thread driver. Four new cases with real contention, recorded natively.
shared-1Runtime code that both translators kept moves into the crate (the owner's rule of 2026-10-05). IoError is generic over the string type, with accessors and the index of its builder. The crate gets the stopping sink of IO.Process.output, Lean's lossy UTF-8 decoding and Task.get's rule (await_task). It also gets IO.getTID, a child object made from a pid, and a hook for the runtime's stderr lines in tests.
wait-1Three wait protocols move into sched (the wait cores). A context waits for a thunk or a constant that another context computes. The single-thread ST.Ref follows Lean 4.35's rule. Promises dropped in a free are resolved after it. A free inside a resolution resolves its own promises first, as natively.
shared-2Startup logic that only lean2rr kept moves into the crate. main runs on a thread of its own with Lean's stack (run_main). The feature startup-fds opens the startup descriptors in the crate's own constructor: the third native quirk. The scheduler can start lazily, at the first task (start_lazy). The crate's constructors use no global allocator (AR-36).
shared-3The panic and exit executor that both translators kept moves into the crate (io::panic). A translator gives its streams through a glue trait, whose defaults are native's behaviour. The internal panic builds its line on the stack, with no allocation.
net-threadsNetworking in threads mode (N): TCP, UDP and name lookups on the loop thread, as natively. The feature net no longer turns on sched. The second test driver runs every net/ case in threads mode, 5 times.

Each batch has its rows or program cases, and benchmark pairs: one per semantics function, and one per hot path of io (Testing). No timing session has run yet.
